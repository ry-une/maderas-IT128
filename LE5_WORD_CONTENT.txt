NOTE ABOUT LOGIN/REGISTER RESPONSE HANDLING
The LE5 PDF's own login sample expects the API to return an object with id_token and id. The REAL BlogAPI LoginController returns only a raw JWT text string with no user id (confirmed by reading LoginController.cs directly, not assumed). To avoid breaking the working LE4 backend, the Angular AuthService and LoginPageComponent were written for the raw-string response using responseType: 'text', and no fabricated user id is saved. This should be called out briefly in the report/reflection section if one is required.

NOTE ABOUT VERSIONS
Angular 15.2.10 was used (Angular CLI 15.2.11, TypeScript 4.9.5) for compatibility with Node 16.16 and the traditional NgModule structure (app.module.ts / app-routing.module.ts) shown in the PDF, since newer Angular majors require Node 18+ and default to standalone components.
