4. POSTMAN
Import: MADERAS_LE4.postman_collection.json
Collection name: MADERASLE3 (kept because the LE4 PDF says <LASTNAMELE3>)
Collection variables:
- baseUrl = https://localhost:7161
- token = automatically populated by Login Request after a successful login

Run the requests in this order for the cleanest grading evidence:

A. Login Request
POST {{baseUrl}}/api/Login/login
Existing valid LE3 account already in BlogDB:
{
  "userName": "rjvmaderas",
  "password": "2024108288"
}
Expected: 200 with JWT. The test script auto-saves it to {{token}}.

B. Register Request
POST {{baseUrl}}/api/Login/register
{
  "userName": "RyanJosephVMader",
  "firstName": "Ryan Joseph V.",
  "lastName": "Maderas",
  "password": "RyanJosephVMader"
}
Expected: 200 "User registered."

IMPORTANT PDF/database conflict:
The PDF asks for the full name with no spaces for username AND password. "RyanJosephVMaderas" is 18 characters, but the existing LE2/LE3 Users table uses NVARCHAR(16) for both UserName and Password. The database schema was intentionally NOT changed. RyanJosephVMader is the 16-character assignment-style fallback.

C. List Post Request
GET {{baseUrl}}/api/Post
Expected: 200 with post list.

D. Post Details Request
GET {{baseUrl}}/api/Post/1
Expected: 200 with post ID 1 details.

E. Add Post Request
POST {{baseUrl}}/api/Post/add
Authorization: Bearer {{token}}
Body:
{
  "title": "Maderas, Ryan Joseph V. has posted this through Postman!",
  "body": "this is a blog post coming from postman!"
}
Expected: 200 "Post created."

5. IF HTTPS FAILS IN POSTMAN
First trust the Visual Studio development certificate if prompted. If Postman reports only a local certificate verification error, either disable SSL certificate verification for local testing or temporarily set the collection baseUrl to http://localhost:5161. Do not change Jwt Issuer/Audience unless the API itself reports issuer/audience validation errors.
